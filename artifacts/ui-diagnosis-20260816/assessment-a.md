# Assessment A — 设计评审（mingli_web 公共 Web UI）

- **评估对象**：http://127.0.0.1:3000 首页 + /bazi /ziwei /qizheng /daliuren /liuyao /qimen /tools /pricing /about /library /daily + Admin 登录页 http://127.0.0.1:3001/login
- **视口**：1440×900、768×1024、360×800（Admin 1440 与 360）
- **与 Assessment B 独立**：本报告不读取、不引用 detector.json / _synthesis-outline.md；console/网络错误不作为评价输入。
- **取证方法（透明声明）**：本代理运行模型不支持图像输入，read_image 不可用。视觉证据来自两条程序化链路，均基于主会话采集的截图与真实渲染页面：
  1. **像素/几何取证**（sharp，对 `screenshots/*.png` 逐像素亮度映射、行墨量统计、画布色差）；tesseract(chi_sim) OCR 提取截图内渲染文本验证折线内容；
  2. **DOM 度量取证**（Playwright，只测量不产生截图）：字阶、行高、元素位置与几何、折叠线内容、表单结构、色值→WCAG 对比度计算、导航项与 mega 菜单项统计、360/768/1024/1440 全部 12 个公共路由无横向溢出。
  所有定量结论均可复验。

## 1. Design-specificity Verdict（这个产品是不是"换了名字也能用"的通用模板脸）

**结论：是。换名即用的程度约 8/10 —— 这是一张"现代 SaaS 中性壳"，几乎不存在任何锁定到"命理/术数/可核对盘面"这个产品的视觉身份。**

证据（全部来自实测）：

- 全站唯一的产品性视觉元素是一个 44×44 的方框"命"字（品牌占位）；任务卡、导航、价格卡全部使用 Lucide 通用功能图标（LayoutGrid / Wrench / CalendarDays / BookOpen / UserRound / ArrowRight），**首页 13 个任务入口卡片没有任何一张带图标**，卡片 = 文字 + 细箭头。
- 首页、八字表单页、工具页、价格页的视觉语言与"项目管理 SaaS 的落地页 + 表单工作台"完全同构：浅灰底 + 白卡 + 1px 边 + 黑按钮。把文案换成 "OKR 对齐工具" 全站可原样上线。
- 没有任何"盘面长什么样"的产品实物：首页首屏无盘面图、无四柱/宫盘缩略、无星盘暗示；用户进入产品前看到的全是文字承诺。
- 好的方面（必须在 verdict 里说清楚）：这不是"杂乱模板风"，而是**纪律极高的中性系统**——token 语义化彻底、边框/圆角/阴影分层一致、焦点环/跳过链接/reduced-motion 齐备、36 个 路由×视口组合全部无横向溢出。它是"做得非常干净的通用脸"，而非"做坏了的脸"。问题在于**合同（DESIGN §2 方向 C「现代 SaaS 锐感」+ 禁止装饰）从源头把产品性格压缩为零**，实现忠实地执行了合同的"无性格"。

**Specificity 评分：1.5/4**（系统质量 4/4，产品辨识度 ≈0/4）。

## 3. 认知负荷检查

Checklist（✓ 通过 / ✗ 失败）：

- ✗ **单一焦点**：首屏同时是"价值主张"+"13 个任务入口"，两者互相抢注意力；DESIGN §6.3 说首页是价值主张+任务入口的混合结构，但落地结果是第一屏全是文字承诺、入口全部排到折线以下。
- ✓ **分块**：卡片按 命盘/事件/见相/合参/辅助 分组，分组合理。
- ✗ **决策点选项数**（核心失败）：有三个决策点超限——
  1. 首页任务入口 **13 个**平级入口（4 命盘 + 3 事件 + 见相 + 2 合参 + 3 辅助），远超 4~7 项工作记忆上限；且无"推荐/新手路径"。
  2. Mega 菜单一次展开 **13 项**（命 5 + 卦 6 + 相 2），合同 DESIGN §6.1 规定 8 项（命 3 卦 4 相 1）；实测 832×356 的大面板把 13 个词平铺，没有主次。
  3. 八字表单一个决策面同时挂 **12 个字段标签**（受测对象/历法/性别/出生日期/出生时间/未知时辰/出生地点/出生时区/时间口径/流年/流月/流日）+ 提交按钮在 1440 首屏 y≈1724（约 3 屏滚动后才到）。
- ✓ **分组**：表单字段分区可见（任务名/模式/说明在顶），分组结构存在。
- ✓ **视觉层级**：单页内 h1→机制→卡片层级清楚。
- ✗ **一次一件事**：命盘 4 卡 + 事件 3 卡 + 合参 2 卡 + 辅助 3 卡在同一屏内连续出现，用户被要求先做"我该进哪一个"的元决策。
- ✗ **最小选择**：见上，三个决策点均 >4 可见选项。
- ✓ **工作记忆**：无跨屏记忆负担（代价是没有复用）。
- ✓ **渐进披露**：工具页的"已接/适配中"pill 与详情披露做得克制。

**小结：认知负荷中-高（5/8 项失败）**，失败的根源不是密度，而是**选择过多 + 无默认路径**。命理初访用户（Jordan）面对 13 个入口时没有任何"从这开始"的锚点。

## 4. 情绪旅程与峰终

- **情绪曲线**：#fafafa 画布上，全程近乎一条直线。首屏（峰值区）的唯一"重音"是 118×44 的黑按钮；全页仅有的三块黑色（CTA、见相黑条 @1291、页脚）全部在折线以下或边缘（首页折线 900px：见相黑条在 1291px）。
- **峰**：不存在。没有一张盘面图、没有一个"哇"时刻、没有任何与"命理/神秘/确定性"情绪相关的视觉锚。
- **终**：黑色页脚 + "© 2026 命理工具测试版"——中性、可信、冷。
- **高利害时刻的安抚**：产品自身文案诚实克制（"不伪造效果""不显示假宜忌"），这在**信任维度**是加分项；但在**情绪维度**，用户到达付费语境（/pricing）时看到的是 ¥0/¥29.90/¥9.90 三个等权灰卡 + 一大段"无 TLS、无真实支付、仅运营开通"的免责说明——理性满分、温度为零。
- **峰终判断**：对"价格 29.9 元的个人命理解读"这种高情绪卷入产品，当前曲线是"工具报表"型；用户记住的是"一个严谨的空壳"，不是"一次被理解或被震撼的体验"。

## 5. 真实优点（2-3 个）

1. **工程级 token 纪律与响应式无溢出**：全部 36 个 路由×视口组合 `scrollWidth ≤ viewport` 实测通过；语义 token 是组件唯一颜色入口（未发现散落硬编码品牌色）；焦点环 2px、skip link、reduced-motion 覆盖整站。这是绝大多数团队做不到的底子，评审不以"没出 bug"为表扬，但**这套设计系统的可维护性是真的**。
2. **状态诚实度是信任资产**："身份未知"（会话降级时）、"工具能力暂不可用/适配中/已接候选事实"、pricing 的"测试期无真实支付"、admin 的 LOCAL 徽章——全部是真实能力边界的面向前展示，没有假盘、假成功、假倒计时（DESIGN §14/§16 落实到位）。在命理品类（满街骗局）里这是差异化卖点，值得保留并外化。
3. **任务页壳的"聚焦输入"模式**：ProductTaskPage 首屏 = 返回链接 + 56px 产品标题 + 摘要 + 「适合处理/当前边界」dl + 430px 单列表单 + 48px 黑提交。它忠实执行了 METIS 式窄面板聚焦合同，比参考站的平铺录入选轻一个量级；八字表单 12 字段全部有 label/hint/disabled-reason，错误预防扎实。

## 6. 优先级问题

### [P1] 首页与全站没有任何产品身份锚 —— "通用 SaaS 模板脸"（specificity verdict 的核心）
- **问题**：首屏文字 100% 是"机制证明"（13 Provider / 55 古籍 / 1328 evidence），零张盘面图、零视觉产物；13 个任务卡无图标无层级。
- **为什么重要**：用户在 5 秒内无法回答"这产品给我什么"。对高卷入的命理产品，这是转化与信任的起点问题；通用脸还直接导致品牌冻结后无处落锚。
- **修法**：① 在首页 hero 右侧/下方放一张**真实的免费四柱/宫盘缩略**（由 Runtime 生成，遵守 DESIGN §8.1），让"确定性盘面"从口号变成可视证据；② hero 主句从"十三术同根…"（工程事实）改为用户受益句，把机制数字降为副标证明条；③ 允许任务卡携带术数专属的领域图形（审核过的干支/卦象符号，Lucide 之外是 DESIGN 允许的"领域图形"），至少让"八字≠紫微"能从图标区分。

### [P1] 首页 13 平级入口 + 命盘 3+1 破行 + Mega 菜单超合同 —— 决策过载与版式失控
- **问题**：① 首页任务入口 13 个，无推荐路径；② 命盘区实际 4 卡（八字/禄命纳音/紫微/七政），七政卡孤悬第二行第一列（1440 实测 y=805，下方两列空）——NATAL_TIERS 三段梯度（lead/标准/tail）在 4 卡时断裂，第二行只剩一张"标准白卡"；③ Mega 菜单实测 13 项 vs 合同 8 项（多出 禄命纳音/太乙/择日/风水，且命盘合参在"命"组与"合参"顶级入口重复）。
- **为什么重要**：决策点全部 >4 项（认知负荷第 3 节）；3+1 破行是折线上最后一个视觉印象，直接给出"没排好"的信号；导航超合同会让 CHECKLIST 产品地图（这些路由不在 §4 路由清单）与 UI 不一致。
- **修法**：① 命盘区按合同回 3 卡（禄命纳音收进 /arts 或"更多术数"卡，与 §6.3 一致），或在 4 卡时用 2×2 网格并明确第 4 卡的弱化层级；② Mega 菜单按 §6.1 收口为 8 项，把 太乙/择日/风水/禄命纳音 移出或在 /arts 总览呈现；③ 首页给"新手开始"一个唯一默认路径（如"开始排盘"直接进入八字）。

### [P1] 首屏无"结果预览"，价格页引用废弃产品词 —— 转化与可信度双重损耗
- **问题**：① 首页首屏无任何"做完会发生什么"的预览；② /pricing 首页折线内经 OCR 确认出现"付费向解读（今日/本周/六爻）仅运营开通"——"今日/本周"是旧 preview/today/week 产品词（CHECKLIST §2.2 已整体重写），当前产品地图里不存在，用户会以字面理解。
- **为什么重要**：命理用户做的是"高风险情绪买单"，没有结果预览 = 没有想象空间；价格页出现用户从未见过的产品名 = 直接怀疑页面过时/套壳。
- **修法**：① 首页在 CTA 后加"示例盘面"入口（合同 §6.3 的次 CTA 文案本来就是「看示例盘面」，当前实现写成了「多术合参」——先把文案合回去），或直接内嵌一个可交互 demo；② 价格页文案同步到当前产品地图（八字主线 + 六爻事件 + 合参），删除 今日/本周。

### [P2] --color-text-muted #8a8a8a 大面积用于 12-13px 元信息，对比度不达标
- **问题**：实测 `#8a8a8a` on `#ffffff` = **3.45:1**、on `#fafafa` = **3.31:1**、on `#f5f5f5`（cardTail）更低，全部低于 WCAG AA 4.5:1；它被用于首页全部卡片的"适合处理"行（12px cardMeta）、分区描述（sectionHead p，13px）、辅助入口描述（auxBody small，12px）——是全站最普遍的次级文本。
- **为什么重要**：元信息恰好是最需要被扫读的"适用边界"信息；低对比 + 12px 双重打击，视觉上发灰（观感"不干净"的元凶之一），对低视力用户直接不可读。
- **修法**：把 `--color-text-muted` 从 #8a8a8a 提到 ≥#6e6e6e（on 白 ≈4.6:1），或对 12px 文本改用 text-secondary 并保留 muted 仅用于装饰性标签。

### [P2] 全站动效/阴影零剧本，hover 微交互不可感知 —— 页面"静止得像文档"
- **问题**：唯一动效是 160ms 的 border/shadow/1px 位移（卡片 hover 阴影仅 5% 透明度）；页面加载无任何入场节奏；全页唯一的"重"是黑块。CV 上没有 motion、没有滚动叙事、没有状态转变的戏剧性。
- **为什么重要**：克制的反面不是炫技，而是"产品是活的"的感知缺失；对未来要收费的内容产品，首屏的"呼吸感"直接影响停留与浏览深度。DESIGN §15 禁止弹跳/滚动劫持，但允许 opacity/transform 的 120-280ms 过渡——当前实现连这个配额的一半都没用上。
- **修法**：① 首页各 section 做 160-240ms 的 stagger 入场（scroll reveal，遵守 prefers-reduced-motion）；② 卡片 hover 阴影从 5% 提到 contract 允许的 `--shadow-card-hover` 上限；③ 给"确定性盘面"一个 280ms 的生成→呈现状态转换，把"计算中→出盘"变成产品记忆点。

### [P3] 其余磨光项（合并）
- h1 字重三家族漂移：首页 700 / editorial(pricing,about) 580 / secondary(tools,library,daily) 620——同一层级的标题三种脸。
- 768 视口 h1 被 clamp 压到 40px（与 360 相同），1024 才是 51px；768 平板首屏标题偏小。
- /library 的"筛选"提交按钮常显灰（enabled 态也是 #eeeeee 底 + 二级文字色），与全站"黑底白字主提交"是两套主按钮词汇。
- 顶栏品牌副标"可核对盘面 · 中性界面"——把工程姿态当品牌口号；"测试版" pill 与副标在 1440 下挤在品牌行内。
- 首页 hero 右侧 1/3 空画布（52rem 栏内左对齐 + 24rem+ 空）；机制条 3 列只有 hairline + 13px 文字，视觉上像"脚注"而不像"卖点"。

## 7. Persona 红旗（具体元素，非泛话）

**Jordan（首次接触的命理小白）—— 第 1 步流失点：13 选 1**
- 首屏没有除 /arts 之外的任何引导；13 个平级入口卡无图标、无推荐、无"新手适合先试哪个"，Jordan 的移动路径是扫一眼 hero（读不懂"reference pack/evidence index"）→ 扫卡片墙 → 关闭。
- "命盘"与"事件判断"的分组语义对新手不是直觉（为什么"八字"在命盘而"六爻"在事件？），术语零解释入口。
- 360 首屏：折叠线前只有 hero + 机制条 + "命盘"标题，**第一张可点任务卡在 y=837（折线 800 之后）**——Jordan 首屏想点但没得点。

**Casey（单手移动用户）—— 无底部快捷路径**
- 底部栏 5 项是 主页/术数/工具/每日/我的，**没有"开始排盘"**；要起盘必须"术数 → 抽屉 → 找到八字 → 进入表单"，比预期的 1 步多 2 步，且表单在 360 下首屏只露第一行字段，提交按钮在 y≈2259（约 3 屏滚动）。
- 出生日期/时间期望快速选择（2×2 或底部选择器，合同 §5 有要求），实现为长表单滚完才见主操作。
