模块以 `service.py` 中的 `ReadingService` 作为对外 API 门面，提供 `start_preview/start_fortune/start_liuyao/supply_input/get_result/follow_up/submit_verification` 等方法；通过 `repository.py` 的 `SqlReadingRepository` 使用 SQLAlchemy 异步会话访问数据库，并对 Prepare/Result JSON 使用 `EnvelopeCipher` 加密存储。

编排核心在 `orchestrator.py`：`ReadingOrchestrator` 基于 `ReadingCheckpoint` 的状态机驱动（INPUT_READY → WAITING_INPUT → PREPARED → COMPLETING → ACCEPTED，并支持 DELAYED/RUNTIME_UNKNOWN），通过 `RuntimePort`、`NarrativeModelPort`、`NarrativeGuardPort`、`PublicCopyAssemblerPort`、`ReadingRepository`、`Clock` 等 Protocol 抽象外部依赖，使编排逻辑可被测试替换。

契约层集中在 `runtime_contracts.py`（Prepare/Complete/Described/Prepared/Accepted/Stopped 等命令与结果类型，借助 `jsonschema` Draft202012 验证）、`model_contracts.py`、`narrative_contracts.py`、`output_contracts.py`、`capability_policy.py`，以及共享的 `status.py`（`ReadingStatus` StrEnum）。

辅助子模块职责清晰：`alerts.py` 定义告警事件与 sink（默认 Noop）、`candidate_reference_closer.py` 关闭候选引用、`narrative_guard.py` 执行叙事守卫、`public_copy.py` 与 `public_fact_panel.py` 负责公开副本与事实面板拼装、`request_compiler.py` 将业务参数编译为 Prepare 命令、`rate_limit.py` 控制速率、`errors.py` 集中异常类型。依赖方向单向：service → orchestrator + repository + contracts；orchestrator 仅依赖 Protocol 与 contracts，不感知 SQL 或 HTTP。
