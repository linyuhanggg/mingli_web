# 梅花易数全流程逐屏规格

流程是同一路由 `/meihua` 上的状态机（DESIGN §7）：

```text
S0 入口态 → S1 起法与录入 → S2 提交确认（inline 摘要） → S3 三卦盘面态（免费） → S4 深读选择/支付 → S5 报告态
                                                          └→ S6 异常态族（贯穿全程）
```

每屏给出：目的 / 布局（360·768·1024·1440）/ **显示内容合同**（区块、字段路径、呈现规则、缺失时行为）/ 交互 / 验收点。字段路径全部对齐 `MeihuaChartViewModel`（`meihua-chart/v1`）——这是五术里类型钉得最紧的一份 view 合同（`core_facts` 四个字段全部显式成形），需要展示但拿不到的数据标 `ALGO-GAP`（编号 `GAP-MH-xx`），汇总在文末。

**通用红线**（同八字/六爻样板）：无 raw JSON / snake_case / 内部 ref；空字段整块不渲染不占位；无合成评分与吉凶（G2）——`hard_verdict`/`event_verdict` 恒为 null，「生体/克体」等极性只作为**古籍已裁定的关系事实**呈现，永不翻译成成败；引文原样透传（G1）；页面级不横滚；四视口 + 键盘 + reduced-motion（G6）。

**梅花特有红线**：客户端绝不做起卦推导——年月日时→上下卦动爻的除余、数字取卦、声数取卦全部只能由服务端完成（Request Compiler 已按方法拒绝非法输入，页面帮助文案已承诺「不会把数字、声音或观测资料改成时间起卦」，UI 不得打破）。`observation`/`supplied_hexagram` 的上下卦是用户输入，回显小图属输入直显，允许。

**游客与登录（2026-08-22）**：S3 是 `/meihua` 上的免费盘面态，不是账户历史页。游客提交后同路由出盘；`/account/history` 的登录墙只挡住「我的历史」，不得挡住刚排出的盘。内部 enum / snake_case / 英文工序句不得上屏；无映射则隐藏，不回退原值。判断无 `accepted_copy` 时用中文诚实空态，不写「服务端尚未返回已接纳正文」。旺衰同一事实只渲染一行，状态说明整表一句。互卦 `null` 仍整列不占位（本轮未测到，规则保留）。

## S0 入口态（pristine）

**目的**：让用户 3 秒内明白「一事一问、五种起法任选其一、得到本互变三卦与体用关系」。

**布局**：

- 1440/1024：术标行（印章「梅花」）通栏；下方双栏——左录入面板 456–496px，右空盘剪影（`MeihuaTriad` silhouette：三个空卦位横列 + 体/用两个空标注位，最小 420px）。
- 768：单列；剪影压缩为三个空卦位横条（高 88–120px）。
- 360：单列；剪影隐藏。

**显示内容合同**：

| 区块 | 显示什么 | 来源 | 规则 |
|---|---|---|---|
| 术标行 | 印章「梅花」+「梅花易数」+ 适用说明（如「以一事一问起卦，看本互变三卦与体用」）| 静态文案 | H1 为术名；≤20 字 |
| 空盘剪影 | `MeihuaTriad` silhouette：本/互/变三个空卦框（各 6 空爻位）+「体」「用」空标注 | 静态结构 | 无示例卦；配「提交后由服务端生成，可核验」 |
| 起法提示行 | 一句：「支持按时间、数字、声数、观察或已有卦象五种起法，按你实际用的方式提交」 | 静态文案 | 五起法是梅花入口的差异卖点，首屏点明 |
| 能力边界行 | 免费确定性盘面 + 体用关系古籍极性可核验；深读按 Offer 状态 | 能力接口 | 不用工程词 |

**验收点**：首屏可见术标行、起法提示、起法选择器、剪影；无编号清单。

## S1 起法与录入

**目的**：五种起法各自只暴露自己需要的字段，来源必填的理由讲清楚。现有 `product-input-form` 的条件渲染逻辑保留，本节钉死每种起法的字段差异与文案。

**通用字段**（所有起法都有）：

| 字段 | 必填 | 控件与规则 |
|---|---|---|
| 当前问题 | 是 | 文本；帮助「一事一卦」 |
| 判断侧重 | 是 | select：结果观察 / 状态变化（现有 `focus` 值 `outcome`/`state` 不变） |
| 事件时间 | 是 | 年/月/日 + 时/分 + 时区 + 地点 + 事件时间口径（民用钟表时间/当地视太阳时，现有控件保留）；帮助「时间起卦以此推卦；其他起法用于月令旺衰」——事件时间在**所有**起法下都参与月令旺衰事实，这点现状没讲清，必须写进帮助句 |
| 梅花起卦方式 | 是 | select 五项（下表）；帮助沿用现有「按实际采用的起法提交，不会把数字、声音或观测资料改成时间起卦」 |

**五种起法差异表**（以 `meihua-chart/v1` 的 `casting_method` 枚举与现有表单接线为准；「文字笔画」不在合同内，见文末说明）：

| 起法 | `casting_method` | 专属字段 | 校验（现有 Zod 合同） | 帮助文案要点 |
|---|---|---|---|---|
| 按时间起卦 | `time` | 无专属字段（用事件时间） | 事件时间完整 | 「按事件时刻的干支数推上下卦与动爻，推导过程在结果页可核验」（核验链见 GAP-MH-01） |
| 按数字起卦 | `supplied_number` | 起卦数字（正整数）· 数字资料来源（必填文本） | 正整数；来源非空 | 来源示例「用户现场报数」；来源必填的原因：「只记录来源，不让系统从自然语言自行猜卦」（现有文案保留） |
| 按声数起卦 | `sound_count` | 声数（正整数）· 声数观察来源（必填） | 正整数；来源非空 | 示例「现场声音计数」 |
| 按观察起卦 | `observation` | 上卦（八卦 select）· 下卦（八卦 select）· 观察来源（必填） | 上下卦已选；来源非空 | 「你观察到的物象对应的卦由你判定并录入；动爻由服务端按事件时间求得，不在此页推算」 |
| 提供完整卦象 | `supplied_hexagram` | 上卦 · 下卦 · 动爻（1–6 select）· 卦象资料来源（必填） | 上下卦已选；动爻 1–6；来源非空 | 「用于已有卦象的复盘核验」 |

**起法切换交互**：切换 select 时专属字段区就地替换（120ms 透明度过渡，reduced-motion 关闭）；已填的专属字段值在切走再切回时保留（本机草稿）；`observation`/`supplied_hexagram` 的上下卦选择器旁即时渲染 `TrigramGlyph` 小卦画（输入直显）。

**360**：上卦/下卦两个 select 并排放不下时纵向堆叠；八卦选项带卦画字符前缀增强扫读。

**验收点**：五起法逐一切换，各自只出现自己的字段；来源字段为空被就近拦截；键盘完整可用；360 无横滚。

## S2 提交确认（inline 摘要）

| 显示什么 | 来源 | 规则 |
|---|---|---|
| 问题 / 判断侧重 / 起法 / 事件时间与口径 | 用户输入回显 | 只回显输入 |
| 起法参数回显 | 按起法：数字、声数、上下卦（`TrigramGlyph` 小图）、动爻、来源说明 | 输入直显；**不显示任何推导出的卦名/互卦/变卦**——那是服务端排盘结果 |

**验收点**：`time` 起法的摘要不出现任何卦（无参数可显）；确认后进入 S3 骨架。

### 游客提交后的路由（2026-08-22 补钉）

| 谁 | 提交「立即起卦」之后 | 登录出现在 |
|---|---|---|
| 游客 | 留在 `/meihua`，切 S3（先骨架后满盘）。禁止 `router.push` 到 `/app/readings/:id` → `/account/history/:id` | 保存、打开历史列表、深读/购买。工作条「更多」可放「登录后可保存这次起卦」，不挡盘 |
| 已登录 | 同路由 S3；写历史是后台事，不要先跳进历史壳再渲染盘 | 深读/购买按 Offer |

登录成功：原地接管当前 `reading_id`，不重填、不重起。对齐八字游客留在 `/bazi` 的既有路径。对照证据：`docs/releases/evidence/2026-08-22-ut-meihua-bazi-timelayer/1440/00-meihua-guest-login-wall.png`。

## S3 三卦盘面态（免费确定性盘面）——本流程的主屏

**目的**：本互变三卦横列一眼扫完，体用关系与月令旺衰作为已裁定事实上屏，古籍极性证据可逐条核验。梅花的 view 合同类型最紧、数据最全（P10-013D 五起法已实测投影成功），这一屏是五术里**最先能做到设计满血**的盘面。

**布局**：

- 1440：工作条通栏 → 起卦依据条通栏 → `MeihuaTriad` 三卦横列通栏（盘面主体，高约 320–380px）→ 下方双栏：左体用关系卡 + 旺衰事实（384–420px），右古籍极性证据流。
- 1024：同上，三卦横列略收紧（卦间距 24→16px）。
- 768：三卦横列保持横向（三卦是梅花的身份，不拆列）——每卦收窄至 ~200px，卦名字号降一档；下方模块单列。
- 360：三卦横列转为「本卦大 + 互变小」两行：本卦（带体用标注）整宽居上，互卦/变卦并排缩略居下，点击缩略卦放大查看；模块单列。
- 章节锚点（768 以下粘性导航）：`盘面 / 体用 / 旺衰 / 古籍极性 / 深读`。

### 工作条

| 元素 | 来源 | 规则 |
|---|---|---|
| 返回 | 路由 | 回入口态，保留表单 |
| 求测摘要 | `question` 截断 + `subject_ref` 标签 | 一行 |
| 更多 | 保存/导出/分享/历史 | 按登录态与能力显隐。游客可见「登录后可保存这次起卦」；点「历史」才进账户墙。游客第一眼必须是盘，不是墙 |

（梅花同六爻，无时间层 chips。）

### M1 起卦依据条（G3）

| 显示什么 | 字段 | 规则 |
|---|---|---|
| 问题全文 | `question` | 原样，超长折叠 |
| 起法 | `casting_method` | 人话标签（按时间起卦 / 按数字起卦 / 按声数起卦 / 按观察起卦 / 提供完整卦象） |
| 起卦参数与推导链 | **VM 无此数据** | 时间起卦的「年支数+月+日=X，除 8 余 N → 上卦」推导链、数字/声数的取卦过程、观察/供卦的用户输入回显——全部标 GAP-MH-01。补齐前本条只显示问题 + 起法标签，不显示「推导过程暂缺」占位 |
| 动爻 | `moving_lines[]` | 「动爻：三爻」；空数组时不渲染该项（静卦） |

### M2 三卦横列（`MeihuaTriad`，盘面主体）

三个卦位横列，每卦 = `HexagramHeader` + `HexagramFigure`（共享组件族，边界见六爻规格同名章节——共享层只管画卦，体用标注在 `MeihuaTriad` 里挂）：

| 卦位 | 字段 | 呈现 |
|---|---|---|
| 本卦（左） | `primary_hexagram.name/upper_trigram/lower_trigram`；动爻标记 `moving_lines[]`；体用标注 `body_use.body.position`/`body_use.use.position` | 卦名 20px 域字；动爻爻画加朱砂微点 + 传统标记；「体」「用」两枚 16px 印章式标注挂在上/下卦旁，体卦侧 1px 墨线加重（体是梅花扫读第一锚点）；上下卦各带 `TrigramGlyph` + 五行小字（`body_use.body/use.element`，按 `--element-*` 染色） |
| 互卦（中） | `mutual_hexagram.*`（可 null） | 同构、无体用标注；null 时整卦位不渲染（三列自动收二列，不留空框） |
| 变卦（右） | `changed_hexagram.*`（可 null） | 同构；null（静卦）时不渲染，本卦标注「静卦」小字事实 |

卦位间用细墨线箭头「本 → 互 → 变」连接（静态装饰线，`aria-hidden`；360 两行布局时省略）。

**交互**（§21.1/§21.4）：悬停/聚焦任一卦的上卦或下卦 → 该三爻组在旺衰事实表、古籍极性证据里的相关条目同步高亮；反向点击证据条目 → 对应卦位高亮。方向键在六个卦位单元（3 卦 × 上下）间移动。语义替代：三卦同步输出语义表格（卦位 × 上下卦/五行/动爻）。

### M4 旺衰事实（`core_facts.seasonal_strength`）

按卦逐行（map：卦名 → 事实对象）：

| 列 | 字段 | 呈现 |
|---|---|---|
| 卦 | map 键 + `trigram` | 「兑（体）」——是否体/用由 `body_use` 对照标注 |
| 月令 | `month_branch` + `season` | 「酉月 · 秋」。季节英文映射：spring/summer/autumn/winter → 春/夏/秋/冬；已是中文则原样 |
| 状态 | `state`（旺相休囚死，或平/衰） | 状态字 16px；不染吉凶色 |
| 状态句 | `status` | **不上每一行**。`calculated_strength_not_verdict` / `calculated` 收成模块题注一句：「月令旺衰是按时令算出的事实，不是吉凶。」全表只出现一次 |

去重：同一 `trigram` + 体用角色 + 月令 + `state` 只留一行。禁止把体卦/用卦因 map 多键重复堆叠。`seasonal_strength` 为 null 整块不渲染。未知 `status` 隐藏，不回退原字符串。完整映射见 `docs/redesign/2026-08-22-meihua-ut-rework.md` §2。

### M5 古籍极性证据（`core_facts.interpretive_candidates`，A 档核心模块）

`relation_candidates[]` 每条一行，这是梅花 A 档相对 B 档多出来的主体内容：

| 列 | 字段 | 呈现 |
|---|---|---|
| 关系 | `source_plate` + `position` + `actor.trigram` vs `body.trigram` + `relation` | 「互卦上卦 离（火）→ 体 兑（金）：火克金」，点击联动 M2 对应卦位 |
| 极性 | `relation_adjudication.source_polarity` | 人话标签：supportive=生扶体 / depleting=泄耗体 / adverse=克制体 / favorable=体所生克 / harmonious=比和。中性 chip + 金线出处徽章，**不用红绿**；标签词表进 GAP-BZ-03 扩表 |
| 月令 | `seasonal_state`（可 null） | 有则小字附注 |
| 出处 | `relation_adjudication.source_refs[]`（pack/rule_id/source_anchor） | `EvidenceBadge` → `EvidenceDrawer`（复用八字 M12 抽屉）显示原文锚点与规则号 |
| 未决检查 | `relation_adjudication.unresolved_checks[]` | 行内折叠 |

模块尾固定中文页脚（只出现一次）：「以上是古籍已裁定的关系极性。这件事成不成、吉凶、应期，本页不断。」（对应 `requires_synthesis_adjudication=true`、`event_verdict=null`）。

`interpretive_candidates.boundary` **禁止英文/snake_case 原样透传**。含 `body/use`、`source-adjudicated`、拉丁长句时丢弃，只保留上句中文页脚。服务端已是通顺中文且不与页脚重复时，可显示一次。

`interpretation_status`：`facts_only` 不进标题（模块名已是「古籍极性」）；`source_adjudicated_relations` → 「古籍已裁定关系极性」。未知值隐藏。`interpretive_candidates` 为 null 整块不渲染。

### M6 免费基础摘要 + 深读入口

同八字 M11/M13 合同：摘要只复述已上屏事实（三卦名、动爻、体用五行关系、旺衰状态），不新增判断；深读入口按 Offer 状态。

**S3 状态清单**：loading（三卦位骨架横列）/ ready / partial（`core_facts=null`：三卦 + 体用卡可用——全是必有字段，M4/M5 不渲染）/ error / unavailable。梅花的 partial 态比六爻体面得多：必有字段已经构成一张完整可读的盘。

**判断区（阅读壳，2026-08-22）**：有 `accepted_copy` 才展示正文。无正文时不写工序句。空态标题「判断」，正文「这一问还没有可发布的判断。上面的盘面和关系事实可以先看。」辅助「不是加载失败。吉凶成败本来就不在这一页。」有盘时盘面在前、判断空态在后，淡墨，不是错误块。生成中：「正文还在生成。三卦盘面可以先看。」

**验收点**：三卦横列 768 不拆、360 两行布局可放大缩略卦；体用标注与 M3/M4/M5 联动；极性无红绿染色、全部带出处徽章；成败/吉凶字样 0 处；页面无横滚。游客提交后可见盘且 URL 不是 `/account/history/…`。可见文本不得出现 `calculated_strength_not_verdict`、`facts_only`、`body/use`、`source-adjudicated`、英文季节、以及「服务端尚未返回已接纳正文」。

## S4 深读选择与支付 / S5 报告态 / S6 异常态族

与八字 S4/S5/S6 同构（bazi-flow-spec 为准），差异：

- S4 SKU 文案面向「一事一问」；样例引用来自体用关系与极性证据。

## ALGO-GAP 清单（算法/后端开发的输入）

### GAP-MH-01 · 起卦依据与推导链未在 ViewModel 暴露（P1，阻塞 G1/G3 核验）

- 缺什么：`meihua-chart/v1` 顶层只有 `casting_method` 枚举；`core_facts` 四字段里没有历法/起卦参数/推导过程。时间起卦的「年支数+月数+日数=X · X÷8 余 N → 上卦」链条是梅花最核心的可核验证据（青囊与传统盘面都完整显示），数字/声数起法的取卦过程同理；观察/供卦起法至少要回显用户提交的上下卦与来源说明。
- 期望的数据形状：`core_facts.casting = { method, lunar_calendar: { year_branch_number, month_number, day_number, hour_branch_number } | null, inputs: { number | count | upper_trigram/lower_trigram/moving_line, source_note } | null, derivation: { upper: { sum, divisor: 8, remainder, trigram }, lower: {...}, moving_line: { sum, divisor: 6, remainder, line } } | null }`——按起法只填相关子块，Runtime 已有这些中间量（P10-013D 编译器按方法组装字段），是投影补充不是算法新增。
- 影响：不补则 M1 只能显示起法标签，「可核验」承诺在梅花页落空。

### GAP-MH-02 · 互卦缺失场景的事实说明（P3，低优）

- 缺什么：`mutual_hexagram` 可为 null，但 schema 未提供「为何无互卦」的状态字段（正常情况下互卦总可求出；null 更可能表示投影分支未覆盖）。
- 期望：确认 Runtime 是否存在合法的互卦缺失场景；若无，把 `mutual_hexagram` 提为必有字段，UI 删除 null 分支。

### 术语释义词表（并入 GAP-BZ-03，不另开编号）

扩梅花词条：体/用、互卦、变卦、动爻、旺相休囚死、五种极性标签（生扶体/泄耗体/克制体/体所生克/比和）。

### 说明：「文字笔画起卦」不在合同内

派单提到的「文字笔画」起法不在 `meihua-chart/v1` 的 `casting_method` 枚举中（实际五法：time / supplied_number / sound_count / observation / supplied_hexagram，P10-013D 已实测）。本规格按实际合同写五法；若产品要求补笔画法，属新增输入合同 + Runtime 起法，需项目经理另立任务裁决，本文不预设。
