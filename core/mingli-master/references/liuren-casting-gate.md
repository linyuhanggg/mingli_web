# 大六壬正式起课门

本文件只处理一个可检验的具体占事。泛问今天/明天整体运势走八字近时路线；出生八字长期命运、正式择日、医学、法律与投资事实调查也不由大六壬替代。

Do not open this reference in ordinary Hermes chat. Hermes 已由 `SKILL.md` 直接给出唯一入口；本文件用于维护、测试和非 Hermes 环境。

## 路由与输入

- “今天运势”“明天运势”走 `bazi near-time`，不得自动转成大六壬。
- 一课只绑定一个问题。原问题的应期、人物或条件追问，以及对前一结论的自然质疑、原题换说法或补充事件背景，都复用同一课；独立新问题才重新起课。
- 当前占事的输入为 `question`、`civil_datetime`、`timezone`；`question` 必须保留用户原话，不得把用户原话改写成摘要后再传给 `liuren_calc.py`。`location` 只作起课地点记录。中国大陆的当前问事默认民用北京时间，并记录 `中国（民用北京时间；城市未提供）`，不用追问城市。不得把被问对象的城市当作起课输入；“她在国外”与“昨天发生的事”只是对象/事件背景，不自动变成地点或历史时点。
- `--datetime now` 由 wrapper 在所给时区内解析，不得先调用 `date`，也不得由模型心算干支、农历、月将、四课或三传。
- 已知输入不得重复询问。When only one hard field is absent, ask only for the one missing input；只有发问者身处境外/跨时区、明确要求真太阳时，或明确指定历史时点时，才向发问者追问会改变计算的城市/时区或具体时间；缺少具体占事时只追问要断的对象或结果，不问城市。
- 用户在下一轮只补“上海”等地点时，仍绑定上一轮原问题，不得把地点文字另起一课。若上轮误问的是被问对象所在位置，忽略该地点，不得写入 `--location`；保留原问题并只要求“按现在起”。
- 用户明确点名六爻、梅花、奇门、太乙、择日等体系时，事件关键词不得把它改路由为大六壬。
- 默认口径：`zi_hour_policy=midnight`、`guiren_profile=official-corrected`、`day_night_profile=civil-double-hour`、`biezhe_profile=daliuren-daquan-body-branch`。变更口径必须显式传参，不得静默切换。

## 生产入口

生产调用、续问绑定和交付规则只以根目录 `SKILL.md` 的 `One Transaction` 为准。本文件不定义第二套命令、临时路径、重试口令或公开门禁流程，也不得覆盖 `scripts/run_reading_transaction.sh` 这一唯一入口。

事务内部负责绑定确定性排盘、事实校验、来源计划、古籍证据、冻结判断和最终交付。维护者可以单独运行底层模块做测试，但普通对话不得照搬维护命令，也不得绕开事务引擎拼装答案。

## 事实硬门

以下事实保持严格一致，文案修订不得改变：

- 民用时间、时区、地点、农历和年/月/日/时干支；
- 月将、天地盘、四课、课体/取传法、三传和旬空；
- 三传六亲、天将与旬内遁干（空亡支为 null），贵人口径、昼夜口径、子时换日和别责 profile；
- 当前问题、source plan、evidence bundle、运行文件哈希。

明示错误必须拒绝，例如把 `丁上戌` 写成 `丁未上戌`、把未将写成午将、把午戌寅写成别的三传、写错旬空或候期日期。若不同实现的四课/三传不一致，先比较时间、节气月将、子时换日、别责口径、算法版本和 source trace，停止公开判断。

固定 720 表只作审计见证；与可追踪古法算法冲突时，保留冲突并采用当前明确配置的古法计算。贵人口径变化只应影响天将布列，不应改动天地盘、四课和三传。

## 古籍依赖

- 主干起例、课体、取传和毕法：`san-shi/daliuren-daquan`。
- 心印、指掌、占类与应期复核：`san-shi/liuren-zhiyin`。
- 类象、五要和专项占法旁证：`san-shi/liuren-miben`。
- 天乙、白虎、青龙、朱雀、玄武等神将只作从属修饰；必要时再用 `shensha-ss-b3-liuren-refinement`，不得以单一神将决定成败。

三书是主干、导读与旁证关系，不是简单多数票。冲突保留书名、版本、规则层和适用条件。书名只有在用户询问出处或解释确有帮助时才公开；证据已由私有 bundle 绑定，公开答复不必逐书报菜名。

## 公开答复

公开答复以 `【玄枢｜MINGLI】` 开头，紧接一个可核验的 `卦象`，再作判断。`课体`、`起课`、`三传`仍是技术术语，但用户可见的总标签固定为 `卦象`，不用 `课象`。

卦象基础字段必须展示：

- 日干支、时干支；
- 月将；
- 课体/取传法；
- 三传支；
- 旬空。

首答默认展开，不把有用内容留给“具体解读一下”以后：除基础字段外，必须有直接主断、决定性的课传过程、与用户问题对应的场景细节，以及事实分辨率边界。四课全文、无关书名和无关建议不必硬塞；但三传六亲天将一旦是主断依据，就要翻译成普通语言，不能藏在私有工件里。

The exact user-visible copy must sound like one person answering another. It needs a direct conclusion to the concrete question and the decisive lesson structure translated into ordinary language. 回答用户实际问的维度；问何时就给有规则支持的传统候期，问金额却无现实量级或校准样本时就直说不能推出精确金额。候期是传统规则候选，不是现实到账保证。

不因题材回避。应酬、赌钱、私下见面、感情隐情、秘密、金钱、难听结果和地点都可以直接断；结论须按本课多项事实收束成“主断 / 次象 / 不主”，而非由一个天将或一个六亲单独编故事。地点可断方位、远近、室内外、场所类型、动静与同伴；除非用户给出待比对候选，不得编造街道、店名或精确地址。不得用“课里不支持直接断成应酬、赌钱、感情秘密或具体地点”一类整类拒绝句替代判断。

除 tag 与“卦象在判断前”之外，不规定标题、句式、段数、固定开场、固定安慰、固定行动建议或固定生活场景。不得把合作、感情、失物、考试、出行等问题改写成回款套话。`妻财`、`兄弟`、青龙、玄武等标签不能单独创造现实事件；若妻财未入三传，也不能直接断“没有工资”，必须结合课传过程与当前问题说明可断和不可断的边界。

## 写作与交付

公开稿必须忠于同一事务冻结的卦象和判断，措辞失败由事务内部修复，不重新起课，也不把内部失败转成用户口令。任何情况下都不得要求用户发送“按原课重写”“按原题重算”或重发原问题。

交付格式、Gateway 私有封套和 Direct surface 规则只以根目录 `SKILL.md` 为准。本文件仅约束大六壬领域判断，不再维护重复的交付协议。

## 非 Hermes 维护路径

只有调试 wrapper、校勘算法或复现用户已给日时干支与月将的完整课盘时，才手工运行 `liuren_fact_adapter.py`、`adapter_validate.py`、`liuren_public_brief.py`、`reading_source_plan.py`、`reading_evidence_bundle.py` 和 `gate_check.py --mode liuren-public`。手工路径仍须保持同一问题与同一组工件，不得低于 Hermes pipeline 的事实和证据标准。
