# Codex 并列顶层 Agent 团队使用说明

> 本文只是根 [AGENTS.md](../AGENTS.md) 的使用说明，不是第二份权威。岗位边界、模型档位、并发上限、消息协议、授权范围和安全规则一律以 `AGENTS.md` 为准；两者不一致时按 `AGENTS.md` 执行并修正本文。

这套团队不再把九个岗位塞进一个项目经理任务的 Subagent 区域。项目经理和九个岗位都是独立的 Codex 顶层任务，固定显示在左侧边栏并置顶；它们能同时工作，也能通过任务消息互相通知。

## 左侧会看到什么

下表是 Codex 顶层任务入口的档位。Paperclip 入口下 UI 设计师与用户测试改用 Grok 4.6 / high，其余相同，依据见 `AGENTS.md` §2。

| 顶层任务 | 模型 / effort | 作用 |
| --- | --- | --- |
| `mingli · 项目经理` | Sol / high | 路由、监控、裁决、验收与用户汇报 |
| `mingli · 状态总结` | Grok 4.6 / high | 可选状态台和日报，不是门禁 |
| `mingli · 前端开发` | Sol / high | Web/Admin/UI 实现，独立 worktree |
| `mingli · 后端开发` | Terra / high | Backend/API/服务，独立 worktree |
| `mingli · 核心算法` | Sol / xhigh | mingli-master 算法，独立 worktree |
| `mingli · UI 设计师` | Sol / high | UI/UX 审查与设计交接 |
| `mingli · 测试工程师` | Terra / high | 技术回归和缺陷证据 |
| `mingli · 用户测试` | Sol / high | 真实浏览器审计与复测 |
| `mingli · 集成发布工程师` | Terra / high | Release Batch、测试预览更新、健康检查与回滚证据 |
| `mingli · 小助理` | Terra / high | 只读查询和资料定位 |

小助理同时承担大内总管职责，是项目经理的直属上级；专业岗位与状态总结的直属上级是项目经理。

九个岗位不是一次性子任务，而是可以继续对话的长期顶层任务。写岗位在独立 worktree 工作，避免同时覆盖主工作树。

## 平时从哪里说话

日常只需要打开 `mingli · 项目经理` 说目标。项目经理把独立工作同时发给对应岗位，并在真正有依赖时才排队。

一句目标默认代表“持续推进到完成或真实阻塞”，不是只触发一次派工。你不需要在每批结束后再输入“继续”“下一步”或“让他们开始工作”。

例如：

```text
让用户测试和 UI 设计师同时审查首页；后端继续订单接口；核心算法继续自己的阻塞项。
不同目录并行，有文件冲突的先告诉我。不要开启 Fast，不要 push 或部署。
```

你可以随时点击左侧任一岗位，直接查看它收到的消息、工具调用、改动和回复；也可以直接在该岗位里追问。但任务范围、Owner 和合并顺序仍由项目经理统一裁决。

## 项目经理怎样持续工作

项目经理按一个循环运行：

```text
拆出当前可执行项
  → 并行派给 2～3 个合适岗位（硬上限 3 条实现或验证工作流）
  → 等待岗位回报
  → 自动转交设计 / 开发 / 测试 / 用户复测
  → 空出岗位槽位后补下一项待办
  → 目标完成或遇到真实用户门禁才结束
```

岗位完成后发来的消息会重新唤醒项目经理。项目经理不能只处理这条回报就收尾，而要同时检查整个目标还有没有可执行工作。等待超时也不算完成；仍有岗位运行就继续等待。

不会强制九个岗位同时忙碌。没有匹配工作、依赖未满足或会造成文件冲突的岗位应当空闲，否则只是白白消耗额度并增加错误。反过来，只要队列里存在至少两条互不冲突、依赖已满足的待办，就必须维持 2～3 条工作流在跑，不得故意串行。

## 岗位怎样主动沟通

每个岗位都收到一份带精确 thread id 的通讯录。确定性问题直接发送，不需要用户复制粘贴：

```text
用户测试 UI_REWORK / UX_REWORK
  → UI 设计师 + 项目经理

UI 设计师 UI_UX_HANDOFF
  → 前端开发 + 用户测试 + 项目经理

开发完成
  → 测试工程师 + 项目经理

技术测试通过
  → 用户测试 + 项目经理

用户测试 PASS
  → 项目经理关单
```

明确的前端、后端或算法功能错误可以直接退回相应开发；归属不清时只让项目经理裁决。每条问题使用同一个 `TEAM_EVENT` 编号贯穿发现、修复和复测，避免重复派工。

## 多条消息同时到达

项目经理可以同时监控九个岗位。消息进入任务队列，按优先级和到达顺序处理；项目经理以事件编号去重，再把独立事件并行派出。

项目经理不写代码、不跑长测试，否则会堵塞收件箱。状态总结只接收抄送并按需汇总，不是流水线必经中转。

只要当前目标还有可执行待办，项目经理就自动填补空闲岗位并继续监听，不要求用户重复发送“继续”。只有目标验收完成、需要用户授权/裁决，或用户明确暂停时才结束当前持续任务。

## UI/UX 工作方式

`DESIGN.md` 是可修订设计基线，不是“照着做就算好看”。数据真实性、状态、响应式、可访问性和技术边界继续有效；审美、信息层级和交互可以被真实用户测试推翻。

用户测试固定给出：

- `PASS`
- `UI_REWORK`
- `UX_REWORK`
- `FUNCTIONAL_BLOCKED`

UI/UX 问题由 UI 设计师出 `UI_UX_HANDOFF`，前端实现，测试工程师回归，原用户测试按同一路径复测。问题未消失就不能 `PASS`。

## Standard 与额度

项目和十个顶层任务全部使用 Standard：`service_tier="default"`、`fast_mode=false`。不会打开 `/fast on`。

并列运行会缩短等待时间，但多个模型同时工作仍会更快使用订阅额度。同时最多运行 3 条实现或验证工作流；整仓构建或浏览器测试等重任务不要并发多份，也不要无意义重复。

## Worktree 与合并

- 前端、后端和核心算法在独立 worktree 写代码。
- UI、用户测试和小助理默认只读；测试工程师只改明确授权的测试/证据文件。
- 岗位完成后主动通知项目经理，不自行合并主工作树。
- 项目经理先检查依赖、测试和文件冲突，再安排合并。
- 不提交、不合并、不 push，不修改生产、数据库、真实凭据或网络/安全配置。
- 唯一已登记测试预览（SSH 别名 `fateradar-prod`，浏览入口 `http://106.14.10.235:18080`）的构建、精确文件同步、测试服务切换/重启、健康检查和失败回滚已获常驻授权，由集成发布工程师在 QA 通过后执行，不必逐批请示。其余远程写入仍须用户在当前任务明确授权。完整边界见 `AGENTS.md` §4 与 §8。

## 运行时通讯录

当前实际任务 id、模型、worktree 和通讯路由记录在项目级 `.codex/team-registry.md`。这个文件用于本机运行时协调，不是产品需求或业务源码。

## 与旧方案的区别

- 旧方案：一个项目经理任务里嵌套子 Agent，最多 3 个，状态岗占一个位置，按批次等待。
- 当前方案：十个左侧可见的并列顶层任务，独立工作真正并行，岗位可以直接消息沟通。
- `.codex/agents/*.toml` 继续保存岗位定义，但项目已关闭嵌套 `multi_agent`，避免再次退回旧流程。

完整路由和边界以根 [AGENTS.md](../AGENTS.md) 为准，模型选择依据见 [Codex 模型路由报告](./codex-model-routing-report.md)。
