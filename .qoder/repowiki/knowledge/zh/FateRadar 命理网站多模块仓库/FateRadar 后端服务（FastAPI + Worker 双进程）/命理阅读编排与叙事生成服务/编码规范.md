- 所有跨进程/跨阶段的命令与结果均定义为 `frozen=True, slots=True` 的 dataclass，并在 `__post_init__` 中调用 `_validate_schema` 进行 JSON Schema 校验，保证契约不变性。
- 外部依赖（运行时、模型、守卫、副本装配、仓库、时钟）统一通过 `typing.Protocol` 声明接口，再由 `ReadingOrchestrator` 注入，便于测试时替换。
- 状态流转集中在 `ReadingOrchestrator.run` 中依据 `ReadingCheckpoint` 字段分派到 `_prepare/_generate/_complete`，并通过 `ReadingOutcome` 返回新状态，避免分散的条件分支。
- 所有持久化写入都通过 `ReadingRepository` 的异步方法完成，且对关键路径（如 `create_version`、`replace_prepare`）使用 `with_for_update()` 行锁防止竞态。
- 输入校验采用白名单策略：`_INPUT_FIELD_POLICIES` 显式声明允许字段及其类型/范围，未知字段直接拒绝，确保只接受产品审批过的运行时输入。
- 幂等性通过 HMAC-SHA256 对 key + action + canonical JSON payload 计算指纹，并以唯一键插入 `ReadingIdempotencyKey` 表，冲突时回滚并重放历史结果。
