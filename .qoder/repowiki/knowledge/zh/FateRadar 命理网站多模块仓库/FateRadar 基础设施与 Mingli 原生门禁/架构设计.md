模块分为两大职责域：
- 生产/本地部署（infra/）：以 `compose.local.yml` 编排 postgres、redis、api、worker、web、edge(Nginx) 六服务；Nginx 配置位于 `nginx/`，通过 `letsencrypt/reload-nginx.sh` 在证书续期后 reload；systemd 单元文件用于独立启动 api/web/worker；SSH 加固与临时首页分别由 `ssh/99-fateradar-hardening.conf` 和 `www/index.html` 提供。
- 门禁与验证（infra/mingli-runtime/ + scripts/）：`local_gate.py` 是单一入口，仅支持 `native-full` profile，通过 `prepared_inputs` 加载已签名输入，用 `SubprocessExecution` 以进程组方式执行固定 argv，强制 600s 超时、8MB stdout/stderr 上限、最多 10 个并发槽位，并输出带 SHA-256 的证据目录；`verify_local_full.py` 作为独立 verifier 二次校验报告一致性；`build_context.py` 从 `.mingli-release-manifest.json` 投影出精确的 Docker build context，锁定 217 个文件及 mode；历史 Linux 模拟实现（Dockerfile、lima-vz-rosetta.yaml、run_lima_gate.py 等）保留仅作追溯，当前流程明确禁止调用。
- 服务端轨迹脚本（scripts/）：`run_server_task13_trajectory.sh` 通过 curl 驱动 API 完成 guest→OTP→profile→readings(preview/today/week/liuyao)→follow-up 完整链路，并以 `sanitize_scan` 扫描输出避免泄露敏感信息；配套 Python 脚本 `task13_trajectory_runner.py`、`server_task13_trajectory_payload.py`、`smoke_local_real_runtime.py`、`verify_frozen_runtime_release.py`、`check_production_secrets.py` 提供辅助能力。
依赖方向：scripts → infra/mingli-runtime（门禁/构建上下文），infra/mingli-runtime 不反向依赖 scripts；部署配置与运行时脚本之间无代码耦合，仅通过约定路径与环境变量交互。
