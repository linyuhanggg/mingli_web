## 1. 设计命题

### 1.1 一句话

**竞品卖「算得准」，我们卖「每一句都能翻回原书第几行」。**

「算得准」是不可验证的承诺；「可核验」是可当场证伪的事实。产品的全部视觉与交互决策都
服从这一条区分。

### 1.2 为什么不能照抄参考站的结果页结构

青囊八字页的结构是「格局 → 用神 → 喜忌 → 病灶诊断 → 行动指南」，它**预设了有断语**。

我方 Runtime 当前的断法覆盖（实测，来源 `.runtime/v53-time-check-release` 的
`references/index/evidence-rules.jsonl`，1328 条规则 / 192 条已激活）：

| 术数 | 已激活判断规则 | 结果页能给什么 |
|---|---|---|
| 八字 | 18（《穷通宝鉴》调候） | 盘面 + 候选链 + 有限古法命中 |
| 禄命纳音 | 56（《李虚中命书》） | 同上，规则最厚 |
| 奇门 | 40 | 局式事实 + 格局谓词命中 |
| 太乙 | 15 | 盘面 + 谓词命中 |
| 大六壬 | 5 | 盘面为主 |
| 择日 | 1 | 盘面 + 淘汰原因 |
| **紫微** | **0** | **只有盘面事实** |
| **六爻** | **0** | **只有盘面事实** |
| **七政** | **0** | **只有盘面事实** |

照抄那套结构，紫微/六爻/七政会得到一整排空槽位；用模型文案填空则直接违反
`DESIGN.md` §17「未接能力展示假盘、假结论」。

**所以页面主体是「盘面 + 可核验的古法命中」，不是「结论 + 依据」。**

### 1.3 三层结构

```
① 盘面层   视觉主体。纯事实，高密度，可视化。不需要任何断语就成立
② 证据层   按需展开。古籍原文 + 为什么适用于这张盘 + 可回溯出处
③ 边界层   明示未裁定。Runtime 说了「候选」就显示候选，不补全成结论
```

三层的比重随术数能力变化：八字/禄命纳音三层齐全；紫微/六爻/七政只有 ① 和 ③。

### 1.4 首屏 30 秒

新用户看不懂术语。在这 30 秒里建立信任只能靠三样**不需要懂术数**就能感知的东西：

1. **时间被认真处理了** — 真太阳时口径完整可见（策略、经度修正、均时差、有效时刻、
   边界状态、晚子时流派）。这是我方唯一能被普通用户直观感知的精度优势。
2. **信息密度** — 盘面本身摆得住。八字 733 条、紫微 346 条可寻址事实路径（实测），
   密度不输参考站。
3. **任一句话可追溯** — 引文旁有可点的出处，点开是原文与行号。

不要在首屏塞结论、评分或营销话术。

## 2. 证据层呈现规格

`DESIGN.md` §8.1 冻结了「格局/喜忌/病药依据」等**槽位**，并明确「只冻结信息架构，
不表示 Runtime 已经产出全部字段」。本节规定这些槽位在 Runtime 只有候选时**怎么填**。

### 2.1 古籍命中卡

数据来源：各术 ViewModel 的 `source_conditioned_patterns`。八字对应
`backend/app/charts/contracts.py` 的 `BaziSourcePattern`：

```
rule_id / local_rule_id / title / source_pack / source_anchor
status: Literal["predicate_matched_not_verdict"]
fact_paths: tuple[str, ...]
predicate_audit: tuple[str, ...]
```

渲染规格：

```
《穷通宝鉴》· 三冬甲木
「冬木寒凝，专用庚金为先（破癸去寒），丁火暖局，戊土堤水。」
  为什么适用：日主为甲 · 月令在亥子丑之一
  出处：bazi/qiongtong-baojian  fulltext.md#L151
```

三个部分缺一不可：**原文**、**为什么适用于你这张盘**、**可回溯出处**。

约束：

- `status` 是类型级常量 `predicate_matched_not_verdict`。文案只能写「此条适用」
  「条件成立」；**不得**写「所以你…」「主…」「宜/忌…」。
- `predicate_audit` 形如 `/day_master/stem:eq:甲`。可以做可读化映射，但**映射表必须是
  显式常量**，不得用模型或启发式猜测；未覆盖的审计串原样显示。
- `fact_paths` 是内部引用，`DESIGN.md` §17 禁止展示内部引用与 snake_case。放开发者视图
  或 `title` 属性，**不得进正文**。
- 原文只能原样透传，不润色、不改标点、不节选到改变语义。

交互定位：**默认折叠的抽屉**，收起态只显示计数（如「命中古法 4 条 · 可核验」）。
它是护城河，但对多数用户是噪音、对怀疑者才有价值，不占主视觉。

### 2.2 候选与未裁定边界

Runtime 的候选层在类型上就写死了不是结论。八字为例
（`BaziStrengthEvidence`）：

```
status: Literal["evidence_only"]
hard_verdict: None = None
```

它提供 `seasonal_state`（旺/相/休/囚/死，带 `seasonal_state_source_rule_id`）、
`same_element_occurrences`、`resource_element` + `resource_occurrences`、
`all_element_occurrences`、`boundary`。

**这些是计数和一个有来源的状态，不是分数。**

`DESIGN.md` §8.1 的「旺衰贡献」槽位应渲染为**证据清单**：逐项列出支持强与支持弱的因素，
并把 `boundary` 声明的未裁定边界原样显示、不折叠隐藏。

`structure`、`following_and_transformation` 是候选，文案必须带候选语义（「候选」
「待裁定」），不得渲染成已确定的格局名。

`reasoning_tools` 是键名不固定的字典，按键遍历；**未知键保留原值原样显示，不猜含义、
不丢弃**（既有规约：不得把 raw JSON 抛给用户，也不得伪造缺失数据）。

### 2.3 术语可读性：定义可以，吉凶不行

用户看不懂术语是真问题，但翻译不能越界。

| | 允许 | 禁止 |
|---|---|---|
| 旬空 | 「日柱所属那一旬中缺位的两个地支」 | 「旬空主虚耗」 |
| 十二长生 | 「该柱天干在本柱地支上的生旺状态位」 | 「墓地主困顿」 |
| 冲 | 「两地支相对，属六冲关系」 | 「冲主动荡不安」 |

判据：**只解释这个词指什么，不解释它意味着什么。**吉凶含义属断法层，须有已核验来源规则
才能出现，且必须走 §2.1 的引文卡形式。

关系类型不得自动染成吉凶色（例如不要把「冲」渲染成红色警示），用中性色区分类别即可。

## 3. 能力分层规则

`DESIGN.md` §8.1 的槽位表对七术一视同仁。本节规定当某术 Runtime 能力不足时页面如何收缩，
以满足 §17「未接能力不得展示假盘假结论」。

### 3.1 三档

| 档 | 条件 | 页面形态 |
|---|---|---|
| **A · 三层齐全** | 有已激活判断规则 | 盘面 + 候选/证据 + 古籍命中抽屉 + 深读 Offer |
| **B · 事实完整** | 盘面事实完整但判断规则为 0 | 盘面 + 明示边界；**不出现断法区块**，不留空槽 |
| **C · 未接入** | Provider 未接或字段缺失 | 「适配中/暂不可用」，永不加载 Fixture（§14） |

当前归档（按 §1.2 实测规则数）：

- A：八字、禄命纳音、奇门、太乙、大六壬、择日
- B：**紫微、六爻、七政**
- C：按 Runtime 实况判定，不预设

### 3.2 B 档的正确做法

B 档不是残缺页，是**只做前两层的完整页**。要求：

1. 盘面区块按 §8.1 槽位表做满（紫微 346 条、七政 311 条可寻址路径，密度足够）
2. 断法/深读区块**整块不渲染**，不显示占位卡、不显示「敬请期待」
3. 页面底部给一条边界说明，说明本术当前只提供确定性盘面与事实，不提供断语
4. 不得因为页面「看起来短」而用模型文案补内容

### 3.3 空值处理

各术 ViewModel 的字段普遍可空（八字 `BaziCoreFacts` 20 个字段全部 `| None`）。
缺字段时**该区块整体不渲染**，不显示「暂无数据」占位条，不用零值或空串顶替。

## 4. 差异化验收：六道门

这是本文的核心。**「超越参考站」必须可判定，不能是「看起来更好」。**

G1–G5 是差异化门，每道都附我方实测证据与参考站实测反例。G6 继承 `DESIGN.md` §18。

### G1 · 引文可核验率 100%

**判据**：页面上出现的每一条古籍引用，抽取后经 `scripts/verify_citation.py` 校验
必须全部返回 `verified_exact`。

```bash
# 从页面/固件抽出引文清单后
python3 scripts/verify_citation.py --file <引文清单>.txt
# 退出码必须为 0
```

**参考站反例（实测）**：青囊八字页标注

> 「偏财源活，最宜食伤生扶；忌比劫劫夺。」——《子平真诠·论财》

在《子平真诠》全文库中 `not_found`，四个关键词组（源活 / 食傷生扶 / 劫奪 / 偏財源）
全部零命中；全库最高 3-gram 包含率仅 8%。且《子平真诠》〈三十三、論財〉原文立场相反
（「財旺無劫而透傷，反爲不利」「傷官本非美物」）。相似度 top3 全在《滴天髓》，
疑为把《滴天髓》论「从财格」的内容改写后挂到《子平真诠》「偏财格」名下。

**这一门参考站结构性做不到**——它们没有 55 部全文库与行号锚点。

### G2 · 零合成断语

**判据**（自动化测试断言）：

1. 页面不存在无来源的总分数值
2. 不存在强弱/吉凶档位条组件
3. 不存在「偏弱」「偏强」这类结论标签
4. 不存在让用户自选档位的「体感校准」控件
5. 当 ViewModel 的 `status` 为 `evidence_only` / `predicate_matched_not_verdict` 时，
   对应区块不得渲染任何结论式措辞

**参考站反例（实测）**：青囊「日主气数」给出
得令 −16 / 得地 −19 / 得势 −3 / 综合分 −38 / 档位「偏弱」，标注「基于《滴天髓》四层考核」。
而《滴天髓阐微》全文 11493 行中既无「四层考核」这一说法，也无任何数值系数
（`grep` 数值零命中）。逐项系数（12基 / 0.60月令 / +0.7系数 / 递减 1.0-0.7-0.4）
均为自研权重挂古籍名号。

**这一门是自我约束，不是能力**——我方有能力做同样的分数条，选择不做。**验收时若发现
任何合成评分，无论多好看，一律打回。**

### G3 · 时间口径完全透明

**判据**：结果页必须可见以下全部字段（来源 `calendar_normalization`）：

1. 时间策略 ID（如 `local_apparent_solar-v1`）
2. 经度修正量
3. 均时差修正量
4. 修正后的有效时刻
5. 边界状态（是否跨时辰 / 跨日）
6. 晚子时流派选择

若修正跨越了时辰或日界，必须明确标出「该修正改变了 X 柱」。

**参考站反例（实测）**：同一输入 `1985-03-02 00:00 北京`

| | 年柱 | 月柱 | 日柱 | 时柱 |
|---|---|---|---|---|
| 我方 | 乙丑 | 戊寅 | **己亥** | **甲子** |
| 青囊 | 乙丑 | 戊寅 | **庚子** | **丙子** |

两家真太阳时都算出 23:33（即前一日晚子时），但日柱不同——**日柱不同意味着整张盘不同**。
两种晚子时流派都合法，问题是青囊在同屏显示「真太阳时 23:33」与次日日柱却不标注流派，
用户无法判断。

**默认态要诚实**：多数盘的修正不跨界，此时它就是一条平静的信息行，不得硬做成戏剧性提示；
跨界时才升级视觉权重。

## 6. 引文核验公开工具页

新增一个不需要登录的公开页：用户粘贴任何一句声称的古籍引文，返回真伪判定 + 原文对照
+ 出处行号。

后端复用 `scripts/verify_citation.py` 的判定逻辑（`verified_exact` /
`partial_match` / `not_found`，含繁简统一与 3-gram 包含率）。

为什么它值得做：

- 零算法风险——只做检索，不下断语
- 可分享，有话题性
- **参考站结构性做不到**，因为它们没有全文库
- 它本身就在展示核心资产（54 部典籍 / 101701 段）

约束：这是工具，不是营销页。不要在页面上点名或对比任何具体竞品，只呈现核验结果。
