# 青囊登录态产品、免费流程与响应式审计

- 审计日期：2026-08-12（Asia/Shanghai）
- 目标站点：https://www.qingnang.cc/
- 会话：用户本人已登录的 Chrome 会话
- 测试边界：只执行明确标注免费的排盘/起局；未进入任何积分解读、充值或账户变更动作
- 虚构命例：男，2000-01-01 12:00，北京市朝阳区
- 虚构问事：`测试：下周项目排期是否顺利？`
- 审计视口：360×800、768×1024、1024×768、1440×900

## 一、结论先行

青囊的产品不是“十三个术数各做一个页面”，而是七个基础能力、三种跨术产品和一组留存/内容/工具能力组成的产品体系。

基础能力分为三组：

1. 命理：八字、紫微、七政四余。
2. 事件：六爻、奇门遁甲、大六壬。
3. 观照：见相。

跨术产品分为三种：

1. 三术合参：八字 × 紫微 × 七政；第二步只在这三术中选择，至少两术，三术全选为旗舰。
2. 问事合参：六爻 × 大六壬 × 奇门；同一问题、同一时刻，一问三断。
3. 参问：八字 × 紫微 × 七政的一问三盘入口，带语言深度、人格风格和后续追问语义。

因此，“13 Provider”只能是 FateRadar Runtime 的内部能力数，不能直接映射成十三个产品入口或十三个单术页面。

青囊的核心商业层级是：

```text
免费确定性盘面 / 规则线索
  → 选择解读维度或合参模式
  → 积分 AI 深读 / 整合裁决
  → 历史、档案、追问与日常留存
```

这比“表单 → 一段 AI 文案”多了一个不可省略的产品层：免费结构化盘面。

## 二、真实导航与页面层级

桌面端“术数推演”使用悬停下拉，宽约 560px；手机端使用全屏术数抽屉。两者的分组一致：

```text
命 · 先天理数
├── 八字 /bazi
├── 紫微 /ziwei
├── 七政四余 /qizheng
├── 三术合参 /hecan
└── 参问 /canwen

卦 · 起局断事
├── 六爻 /liuyao
├── 奇门遁甲 /qimen
├── 大六壬 /daliuren
└── 问事合参 /wenshi

相 · 观照见性
├── 见相 /jianxiang
└── 藏经阁 /wiki
```

一级导航另有：三术合参、百宝袋、每日时令、藏经阁和登录账户入口。

登录账户菜单实际包含：

- 个人中心 `/profile`
- 命盘档案 `/profile/archives`
- 历史记录 `/history`
- 积分获取 `/credits`
- 刷新用户数据
- 退出登录

个人中心不是一张资料卡，而是五个区块：命盘、积分、邀请好友、偏好、安全。偏好又包含解读人格、输出深度和三套皮肤（华彩、素简、墨夜）。

## 三、已验证的免费真实流程

### 1. 八字 `/bazi`

输入层：称谓、性别、公历/农历/四柱、年月日时、国内三级地点/海外搜索、高级选项、档案复用。

免费结果实际包含：

- 四柱摘要、真太阳时、农历、节气、星期、生肖、星宿；
- 年月日时四柱、十神、藏干、纳音、空亡、地势、自坐、神煞；
- 日主气数与四层旺衰贡献；
- 动态变局；
- 子平格局与滴天髓旺衰双视角；
- 喜忌、格局、病药、推理依据；
- 大运、流年、关键流月；
- 智能四柱图示、特殊宫位、五行力量；
- 档案保存、同盘灯与 AI 深读入口。

免费盘面内还提供单年精探入口（20 积分）和总深读入口，但本次未点击。

### 2. 紫微 `/ziwei`

免费结果实际包含十二宫命盘、宫位交互、主辅杂曜、三方四正、四化、格局、命宫性格、大限与流年。AI 详批是后续独立入口。

### 3. 七政 `/qizheng`

页面标记“公测中”。免费结果实际包含星盘 SVG、命度/身度、命盘格局、功能十二宫、十一曜宿度、恩用仇难、大限小限和神煞落宫。后续可选单维 50、全面 100、单年 20 积分，均未点击。

### 4. 奇门 `/qimen`

先选七类场景之一，再输入问题、时刻和地点。起局免费。免费结果包含阴/阳遁局、九宫、九星、八门、八神、值符值使、用神锚点、关键格局和大局基调。AI 推演后置，单场景 50 / 全面 100 积分。

### 5. 大六壬 `/daliuren`

问题 + 可选侧重 + 时刻地点。起课免费。免费结果包含天地盘、四课、三传、九宗门、天将、课体候选、关键神煞和盘面综览。AI 推演后置，单次 50 / 全面 100 积分。

### 6. 三术合参 `/hecan`

三步固定为：立命 → 择术 → 互证。

第二步只出现八字、紫微、七政；至少两术，三术全选为旗舰。页面用十个维度说明每术的主理、参证和不入边界。

免费三盘互证结果：

- 10 个维度有信号，8 维达到两术以上互证；
- 共 53 条线索：八字 8、紫微 23、七政 22；
- 硬规则 37、软引擎判断 16；
- 正向与留意信号分列，不平均、不抵消；
- 整合详批 300 积分，未点击。

### 7. 问事合参 `/wenshi`

同一问题先由用户完成六爻系统摇卦，再以同一时刻生成六壬与奇门。免费结果给出三张可展开盘面：六爻、六壬、奇门；整合详批 200 积分，未点击。

### 8. 免费行为对账户的影响

全部测试前后积分均为 50，未发生扣减。免费排盘、起局和免费合参概览没有自动写入历史记录；历史页仍显示“暂无推演记录”。未点击“存为档案”，档案仍为空。

## 四、双人关系产品

八字、紫微、七政各自都有单人/双人模式切换：

- `/bazi/hepan`

## 六、响应式实测

### 导航断点

- `767px` 及以下：精简顶栏 + 固定五项底栏（首页、术数、百宝袋、每日、我的）+ 全屏术数抽屉。
- `768px` 及以上：完整桌面顶栏，取消固定底栏。
- 断点实测为 768px，不是估计。

### 首页

- 360：术数产品卡单列，无页面级横向滚动。
- 768 / 1024 / 1440：基础术数卡三列；问事合参、见相使用整行卡；每日与百宝袋双列。
- 1440：主体内容最大宽约 976–1104px，不无限拉宽。

### 八字输入页

- 360：表单外框约 304px、内容约 224px；性别双列、地点三列、日期与时间四列；无页面级横向滚动。
- 768 及以上：表单固定约 670px，内容约 590px，居中展示。
- 参考站短板：360 下年月日时仍硬塞四列，单格外框约 47px，真实 `select` 可点击区域约 21×20px，偏挤。FateRadar 不应照抄这一点，应在小屏改成 2×2 或使用底部选择器。

### 八字结果页

- 360：四柱继续四列；明细表约 306px；大运流年卡由十列降为五列；特殊宫位与五行力量上下堆叠。
- 1440：结果主体约 672px；日主气数由单列变成 `100px + 522px`；大运流年十列；特殊宫位与五行力量双列。
- 两档均无页面级横向滚动。

### 紫微结果页

- 360：十二宫盘压成 4×4，盘宽约 316px；格局、星曜、运限等模块逐层单列；无页面级横向滚动。
- 个别宫位副标题使用截断，这是信息密度换空间，不是横向溢出。

### 七政结果页

- 360：主星盘 SVG 自适应为约 322×322；宫位、格局、十一曜和大限模块按 1/2/3/5 列组合重排；无页面级横向滚动。

### 三术合参结果页

- 360：维度列表与价值说明上下堆叠，价值卡单列。
- 1024：主内容仍上下堆叠，价值卡两列。
- 1280（Tailwind `xl`）起：主维度区与价值/付费区变为左右双栏；1440 实测约 698px + 664px。

## 七、参考站本身存在的问题

1. 六爻 `/liuyao` 每次冷导航都可复现 React #418 文本水合错误。页面仍可用，但这通常说明服务端和客户端渲染的动态时间文本不一致。FateRadar 应由服务端传入同一 `now`，或挂载后再显示当前时间。
2. 八字手机端年月日时控件过度压缩，触达区域偏小。
3. 部分复杂盘面在手机上依赖极小字号与截断；适合保留信息结构，不适合原样复制尺寸。
4. 客户端控制台每次加载都会输出“抄袭本代码者……”装饰日志；不属于产品能力，也不应复制。

## 八、对 FateRadar 的直接约束

1. 自有 Runtime 永远是算法与事实权威。
2. 青囊只提供产品模式、用户旅程、信息架构和免费/深读分层依据。
3. METIS 公开 MIT 仓库只作为可迁移的表现层代码来源；其中浏览器排盘、示例数据和业务状态必须删除。
4. 首期 UI 可以预制所有已确认页面与空/加载/禁用状态，但算法未接入的区域必须显示“能力待接入”，不能展示假结论。
5. 三术合参不是十三术选择器；其择术页固定为八字、紫微、七政。
6. 问事合参固定为六爻、六壬、奇门。
7. 盘面与深读必须是两个独立产品合同；严禁把 Runtime 通用 `fact_panel` 或截断 JSON 当用户结果页。
8. 响应式验收必须固定 360、768、1024、1440 四档，并加入页面级横向溢出、导航切换、盘面缩放/重排和真实表单输入检查。
