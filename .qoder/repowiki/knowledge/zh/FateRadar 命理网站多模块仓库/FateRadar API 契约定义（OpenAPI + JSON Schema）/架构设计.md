本模块为纯契约目录，不含可执行代码，分为两个子目录：
- `openapi/`：三个独立的 OpenAPI 3.1 文档，分别描述不同边界——`v1.yaml` 是面向终端用户的 FateRadar API（Health / Identity / Profiles / Readings 四大 tag），`admin-v1.yaml` 是仅员工使用的管理后台接口（独立 cookie 命名空间 `mingli_admin_session`），`internal-model-v1.yaml` 是公司内网独占的叙事生成端口 `/internal/model/v1/generations`。
- `schemas/`：JSON Schema Draft 2020-12 文件，定义跨服务可移植的 Mingli 协议载荷，包括会话 (`auth-session.schema.json`)、健康检查 (`health.schema.json`)、命令流 (`mingli-command-v2.schema.json`，以 `kind` 字段区分 describe/prepare/complete 三种状态机动作) 和结果流 (`mingli-result-v2.schema.json`，以 `kind` 区分 described/prepared/accepted/stopped)，以及输出契约与候选结构 (`mingli-output-contract-v1.schema.json`、`mingli-narrative-candidate-v1.schema.json`)。
依赖方向单向：`internal-model-v1.yaml` 通过 `$ref: "../schemas/mingli-result-v2.schema.json#/$defs/readingBrief"` 等相对路径引用 schemas 中的 `$defs`，使 OpenAPI 文档复用同一份 JSON Schema 作为数据约束；公共 API 的 `components/schemas` 则自包含所有请求/响应类型，不反向引用 schemas 目录。
