# Auth-aware App Shell and Personal Center Rebuild

记录日期：2026-08-11（Asia/Shanghai）

状态：**Web 登录态产品壳、我的首页与个人中心已重建并完成本地验证；账户扩展能力仍需后端合同。**

## 这次解决了什么

- 公共导航会依据真实服务端会话显示“登录”或“已登录 · 我的首页”。
- 私人区在桌面侧栏和手机底栏持续提供“我的首页、命理档案、一事一问、解读历史、个人中心”。
- 私人页头持续显示游客状态或服务端返回的脱敏登录身份。
- `/app` 明确定义为“我的命理首页”，继续使用服务端档案与解读记录安排下一步。
- `/account` 改为登录态互斥页面：游客看到 OTP；已登录设备不再看到重复登录表单，而是看到个人入口、身份和当前设备退出。
- 唯一会话 Provider 提升到根布局；OTP 成功后等待同一 Provider 确认登录，再进入 `/app`，避免兄弟布局重复探测和检查态闪烁。
- 设备会话过期或被服务端撤销时，后端 401 只清除失效的设备与 CSRF Cookie；前端随后重建 Guest Session，因此重新发送 OTP 不会卡在 403 循环。
- 任一私人 API 返回 401 时会使全局身份状态失效，不会让页头继续错误显示“已登录”。
- 从另一个标签页退出后，旧标签页重新获得焦点或恢复可见时会复核会话，不长期残留脱敏身份。
- 客户端换页后由持久的根路由策略将键盘焦点移到新的主内容区，并保留 skip link 与 reduced-motion 行为。

## 没有伪造的能力

当前账户合同只返回用户标识和脱敏登录身份，因此本轮没有虚构昵称、头像、设备列表、订单、支付、权益、导出或删除状态。这些能力需要新的 API、数据模型、鉴权和审计计划。
