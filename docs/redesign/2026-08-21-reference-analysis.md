# 青囊 / METIS 逐点分析：他们为什么这么做，我们怎么处置

每条固定四栏：**做法 → 他们为什么这么做 → 处置（采用/改编/拒绝）→ 落点**。落点指向 `DESIGN.md`（2026-08-21 重写版）章节或 `docs/redesign/2026-08-21-bazi-flow-spec.md`（下称 flow-spec）。

先说结论：两家真正值钱的不是皮肤，是**「盘面是产品的脸」**这个共识。青囊把免费确定性盘面做成信息完备的按柱矩阵，METIS 把「输入 → 同页出盘 → 时间层」做成一条不断的任务流。我们现状恰好两头都丢了：五术页面共用一套「大标题 + 表单 + 编号承诺清单」文档式模板，提交前看不到任何盘的影子；提交后盘面被摊平成一条定义列表流（runtime-bazi-owner-result 实测：十神 14 项挤在一行 definition 里，四柱只占首屏极小区域）。本轮重设计的主轴就是把盘面请回主位。

## 一、青囊

### Q1 免费确定性盘面 → 积分深读 的两层商业结构

- 做法：每术免费给出信息完备的结构化盘面，AI 深读是盘面之后的独立付费入口。
- 为什么：盘面是零边际成本的信任品，先让用户拿到「可核对的东西」，付费才有锚点；同时把贵的 AI 调用挡在付费后。
- 处置：**采用**（已是现有合同）。补一条纪律：免费盘面不做「阉割版」，事实层全量给足，深读卖的是判断与整合，不是卖字段。
- 落点：DESIGN §7、§8；flow-spec S3/S4。

### Q2 按柱矩阵的排盘明细表

- 做法：八字结果的核心是一张列=四柱、行=事实类别（十神/藏干/纳音/长生/神煞/空亡）的矩阵，外加大字四柱卡。
- 为什么：八字的一切事实天然按柱归属，列对齐让「看一柱」和「看一类」都只需一次眼动；这是几百年纸上排盘的版式，用户的心智模型就长这样。
- 处置：**采用（这是本轮最重要的单条结论）**。现状把这些事实拆成纵向定义列表，密度合规但不可扫读。重建为 `BaziPillarMatrix`：列=年月日时，行=事实类别，日主格高亮，行头可点出释义。
- 落点：DESIGN §7.2、§13；flow-spec S3-M2。

### Q3 大字干支 + 五行着色

- 做法：四柱天干地支用大号衬线字，按五行染色（木青火赤土黄金白水玄）。
- 为什么：干支是盘的原子，大字衬线制造「盘」的仪式感；五行色是领域内约定俗成的类别编码，行家一眼读出格局轮廓。
- 处置：**改编**。采用大字宋体域字 + 五行域色，但立两条界：五行色只染盘面事实（干支/星曜/爻/卦），永不用于按钮、链接、状态、吉凶；色值全部按宣纸底重校到 AA 对比。拒绝青囊的高饱和彩色徽章墙。
- 落点：DESIGN §3（`--element-*`）、§4；flow-spec S3-M2。

### Q4 日主气数评分与档位条（得令 −16 / 综合 −38 /「偏弱」）

- 做法：把旺衰合成带数值系数的总分和强弱档位，标注「基于《滴天髓》四层考核」。
- 为什么：用户想要结论，数字显得客观、专业、可比较。
- 处置：**拒绝**。《滴天髓阐微》全文并无「四层考核」与任何数值系数（G2 实测反例）；这是合成断语，正是我们的差异化对立面。我们渲染 `interpretive_candidates.strength` 的证据清单：月令状态（带出处）、同类/生扶计数、未裁定边界原样可见。
- 落点：DESIGN §17、§19.2、§22-G2；flow-spec S3-M5。

### Q5 星宿吉凶、神煞吉凶染色

- 做法：结果页直接给「星宿吉凶：吉」，神煞按吉凶染红绿。
- 为什么：降低理解门槛，制造情绪反馈。
- 处置：**拒绝**吉凶标注与吉凶染色（无已核验断法来源）；**改编**其「悬停神煞查看释义」交互——释义只做定义不做吉凶（§19.3），来源见 flow-spec GAP-BZ-03。
- 落点：DESIGN §19.3；flow-spec S3-M2 交互。

### Q6 命/卦/相 三分导航与产品体系

- 做法：术数按「命·先天理数 / 卦·起局断事 / 相·观照见性」分组；合参是独立跨术产品，不是十三术选择器。
- 为什么：分组按「用户带着什么问题来」而不是按算法家族，选择成本低。
- 处置：**采用**（已是现有合同 §6.1）。本轮五术主线在导航中优先露出，暂缓术不撤导航但不占首屏。
- 落点：DESIGN §6。

### Q7 手机端固定五项底栏 + 全屏术数抽屉

- 做法：767px 以下固定底栏（首页/术数/百宝袋/每日/我的），术数打开全屏分组抽屉。
- 为什么：移动端主任务入口常驻拇指区，比汉堡菜单少一跳。
- 处置：**采用**（已是现有合同 §6.2）。
- 落点：DESIGN §6.2。

### Q8 360px 下年月日时硬塞四列窄控件

- 做法：小屏保持四列，单格可点区约 21×20px。
- 为什么：省纵向空间，代价是触达性。
- 处置：**拒绝**（已有禁令）。小屏 2×2 或分步选择。
- 落点：DESIGN §5、§17。

### Q9 输入页：档案复用、三级地点、高级选项折叠

- 做法：称谓/性别/历法/年月日时/三级地点/海外搜索/高级选项/档案复用一屏完成。
- 为什么：命盘输入是高频重复动作，档案复用把二次成本降到一次点击。
- 处置：**采用**（大部分已实现）。补：高级选项里的时间口径、晚子时策略要有一句人话说明，不是裸术语。
- 落点：flow-spec S1。

### Q10 免费行为不自动写历史、档案显式保存

- 做法：免费排盘不入历史；「存为档案」是显式动作。
- 为什么：游客低摩擦试用，数据留存以用户主动为界。
- 处置：**采用**（符合现有游客合同 §7.1）。
- 落点：DESIGN §7.1。

### Q11 装饰性控制台日志、React #418 水合错误

- 做法：控制台输出「抄袭本代码者……」；六爻页冷导航稳定复现文本水合错误。
- 为什么：前者是玩笑，后者是动态时间文本没走服务端一致渲染。
- 处置：**拒绝**。时间文本由服务端传 `now` 或挂载后再显示。
- 落点：DESIGN §18 验收项。

## 二、METIS

### M1 任务入口 → 单页输入 → 同 URL 即时进入工作台

- 做法：`/chart` 提交后 URL 不变，页面从输入态原地切换为全屏盘面工作台。
- 为什么：排盘是一个任务不是三个页面；不跳转就不丢上下文，回退语义也干净。
- 处置：**采用**。五术统一「入口态 → 盘面态 → 报告态」同路由状态机；`/workbench/[handle]` 只做深链恢复（现有合同）。URL 用不透明句柄，拒绝 METIS 把生辰明文放 URL。
- 落点：DESIGN §7；flow-spec S0–S3。

### M2 盘主文辅双栏工作台（左盘 520px、右读自适应、各自滚动）

- 做法：≥1024px 左侧固定盘面、右侧解读流，两栏独立滚动。
- 为什么：盘面是坐标系，读文时要随时回看；双栏让「看盘」和「读文」并行。
- 处置：**采用**，两处改编：断点提到内容真正容得下的位置（右栏 ≥360px，768px 纵向堆叠——METIS 在 768 强行双栏右栏只剩 237px 是实测缺点）；左盘宽 480–520px 与现有合同一致。
- 落点：DESIGN §5、§7.2；flow-spec S3 布局。

### M3 时间层顶栏（本命/大限/流年/流月/流日/流时）

- 做法：工作台顶部一排时间层页签，切层时盘面原地叠加流曜流化，保留本命参照。
- 为什么：时间层是命理产品的核心纵深，做成页签让「同一张盘在不同时间下」成为一个连续心智对象。
- 处置：**采用**。层由各术 ViewModel 的 `time_layers[]` 声明；不可用层可见但 disabled 并写原因（现状八字 owner 结果的流年/流月/流日就不可用，见 flow-spec GAP-BZ-01）。切层不卸载盘面容器（§21.2）。
- 落点：DESIGN §7.2、§21.2；flow-spec S3 工作条。

### M4 流派设置不是模糊「高级设置」，是 9 类可解释规则

- 做法：主星亮度、庚年四化、晚子时、闰月归属等每条流派选择都写明含义。
- 为什么：流派差异是紫微/八字争议的根源，摊开讲比藏起来更可信。
- 处置：**改编**。我们不做全套流派切换（算法权威在 Runtime），但把同一诚实姿态用在 G3 时间口径上：策略 ID、经度修正、均时差、晚子时口径、跨界标注全部可见。修正不跨界时是一行平静信息，不做戏剧化提示。
- 落点：DESIGN §22-G3；flow-spec S3-M1。

### M5 缺出生地的两段式确认

- 做法：日期齐但没填出生地，第一次提交原位提示「强烈建议填写」，第二次同一按钮放行。
- 为什么：既不硬拦（很多用户真不知道），又保证知情。
- 处置：**改编**。意图采用，形式改为显式确认弹层：「未填出生地：按东经 120° 标准时排盘，不做经度修正」+ 确认/返回补填。连点同一按钮两次的隐式语义是实测缺点，不抄。
- 落点：DESIGN §7.1；flow-spec S2。

### M6 提交前摘要 + 时分即时显示对应时辰

- 做法：输入页底部实时汇总将要提交的资料；填时分即显示对应时辰。
- 为什么：出生资料错一位全盘皆错，提交前给一次廉价的核对机会。
- 处置：**采用**摘要；时辰提示**改编**——民用钟表时辰映射可作输入提示，但必须带「未含真太阳时修正，以结果页时间口径为准」边界（真太阳时可能移时辰，那是 G3 的事）。
- 落点：flow-spec S1、S2。

### M7 雷达图 + 核心优势/关系模式/成长课题 主题卡

- 做法：右栏顶部放性格雷达和三张主题总结卡，正文按主题展开。
- 为什么：给「先看结论」的用户一个入口，降低长文压迫感。
- 处置：**主题导航采用，合成主题卡拒绝**。雷达图和「核心优势」是无来源合成（G2 禁）；但「长文要有主题导航」是对的——报告态用 §9 的主题导航 + 原子判断卡实现，判断卡逐字来自带出处的 public_text。
- 落点：DESIGN §9；flow-spec S5。

### M8 Free / Pro 权益对照页

- 做法：免费与专业版一张表对照，权益范围明确。
- 为什么：付费边界透明本身是转化工具。
- 处置：**采用姿态**：权益由真实 capability/entitlement 驱动；无真实 Offer 显示「测试期未开放」，不伪造价格表（现有合同 §11）。
- 落点：DESIGN §11；flow-spec S4。

### M9 iframe 双应用、hydration 错误、结果页 URL 明文生辰

- 做法：`/sanji-map` 全屏 iframe 加载独立应用；结果 URL 携带出生参数。
- 为什么：省一次架构统一的成本。
- 处置：**拒绝**全部三项（现有合同已禁）。
- 落点：DESIGN §7、§17。

### M10 结果页超长单列（手机 7700px）无章节导航

- 做法：手机端盘面+解读纵向排到 7700px。
- 为什么：内容多，没做定位设施。
- 处置：**拒绝原样**。手机盘面态必须有粘性章节导航或折叠（现有合同 §7.2）；flow-spec 给出八字的具体章节锚点清单。
- 落点：DESIGN §7.2；flow-spec S3 移动布局。

## 三、对我们现状的三条硬批评（重设计动机）

1. **品牌断崖**：首页是宣纸、水墨、印章（用户判定勉强可用），点进任何产品页立刻跌回白底灰字的文档模板。视觉语言在最关键的一跳上断裂。处置：宣纸-墨-朱砂语言全站 C 端统一，首页从「例外」变成「源头」。落点：DESIGN §2、§3。
2. **五术同模板，无领域身份**：八字/紫微/六爻/梅花/大六壬共用同一套「大标题 + 表单 + 编号承诺清单 + 绿色状态框」，编号清单是文档不是产品。处置：入口态右侧改为各术**空盘剪影**（四柱空格矩阵 / 十二宫空盘 / 六爻空塔 / 三卦空列 / 天地盘空环）——诚实（无假数据）、教学（预告结构）、且五术一眼可分。落点：DESIGN §7.1；flow-spec S0。
3. **盘面被摊平成定义列表**：真实签名结果把十神、藏干、纳音逐条塞进 `<dl>` 行（一行 14 项十神），密度合规但不可读。处置：Q2 的按柱矩阵重建。落点：flow-spec S3-M2。

## 四、taste skill 边界声明

taste skill（anti-slop 前端纪律）本轮管三件事：入口页与公共页的气质、反 AI-tell 禁令（无装饰性眉标/无假精确数字/无重复 CTA/文案自审）、状态完整性习惯。它自己声明信息密集多步产品 UI 不在射程内——盘面态的密度与交互跟两份实站审计和 DESIGN §21 的交互质量合同，不跟 landing-page 的留白教条。设计判读与三档旋钮记录在 DESIGN §2。
