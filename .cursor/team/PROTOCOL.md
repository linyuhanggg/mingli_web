# 白板协作协议

这个仓库在 Cursor 里用「共享白板」模式跑多角色协作：角色之间**不互相发消息**，只读写同一份 `BOARD.md`。

## 为什么不是互相聊天

聊天式协作会自发产生寒暄、转发和广播，这些都要付 token，而且状态活在对话历史里，会话一断就丢。白板上没有收信人，只有事实；状态在文件里，跑崩了下一轮读一遍就能接上。

## 角色

项目经理是你在 Cursor 里直接对话的那个主 Agent，不是子 Agent。它读白板决定下一刀派给谁，用 Task 工具拉起对应角色，收到结果后接着派下一个。

八个执行角色是 `.cursor/agents/` 里的子 Agent：

| 角色 | 子 Agent 名 | 负责 |
| --- | --- | --- |
| 前端开发 | `frontend-dev` | `web/**`、`admin/**`、`ui/**` |
| 后端开发 | `backend-dev` | `backend/**`、API、服务层、数据合同 |
| 核心算法开发 | `core-algo-dev` | `core/mingli-master/**`、算法合同与金样 |
| UI 设计师 | `ui-designer` | 界面方案与交接，不写产品代码 |
| 测试工程师 | `test-engineer` | 技术 QA、聚焦回归、缺陷证据 |
| 用户测试 | `user-tester` | 真实浏览器端到端审计与复测 |
| 集成发布工程师 | `release-engineer` | 测试预览发布、健康检查、回滚 |
| 状态总结 | `status-reporter` | 状态摘要与阻塞提醒，只读 |

## 白板结构

`BOARD.md` 分三段，各有明确的写入者：

- **当前目标** — 只有项目经理写。这次要达成什么、验收长什么样、什么时候算完。
- **在办** — 只有项目经理写。每行一刀，包含编号、事项、Owner、状态、允许写的路径。
- **交接日志** — 只追加，谁干完谁写。项目经理不改已有条目。

「在办」的状态只能是 `待派`、`进行中`、`阻塞`、`已完成`、`已取消` 之一。`已完成`、`阻塞`、`已取消` 是终态，其余会被 stop 钩子视为还有活要干。

## 交接记录格式

角色干完活，在交接日志追加一条，格式固定：

```
### [T-007] 前端开发 → 测试工程师 · 2026-08-21 14:02
状态: DONE
改动: web/src/components/task/product-input-form.tsx
证据: vitest product-validation-labels 8 passed
下一步: 验证空提交 /liuyao 与 /meihua 摘要标签是否与可见 label 一致
```

`状态` 只能是 `DONE`、`BLOCKED`、`FAIL` 之一。`BLOCKED` 必须写清卡在什么上、需要谁做什么才能解开。`FAIL` 用于验证不通过，要退回给谁写在 `下一步`。

## 两个钩子

`.cursor/hooks/board-append.js` 挂在 `subagentStop` 上，每个子 Agent 结束时往交接日志追加一行 `auto` 审计记录，写明角色、结束状态和实际改了哪些文件。它不替代角色自己写的交接记录——那条有意图和下一步，审计行只有事实，用来发现「角色说改了 A 其实动了 B」这类问题。

`.cursor/hooks/board-continue.js` 挂在 `stop` 上。回合结束时如果「在办」里还有非终态的行，而且白板在最近 30 分钟内被动过（说明确实在跑），它会自动让项目经理接着派下一跳，不用你说「继续」。白板干净、或者已经放了很久没动，它就什么都不做。上限 20 跳。

## 硬规则

- 一刀只有一个写 Owner。路径冲突时项目经理先裁决，不要两个角色同时改一个文件。
- 只改派单里明确列出的路径。工作树里有大量他人未提交的有效改动，不得 reset、checkout、clean、stash、覆盖、格式化或顺手提交。
- 不 commit、不 push、不改生产。
- 角色不派活给别的角色，只写白板。派活是项目经理的事。
- 没有派到活就静默退出，不要为了显得在干活而制造任务。
