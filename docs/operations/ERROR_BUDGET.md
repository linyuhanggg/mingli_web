# 错误预算策略

版本：v1（2026-08-12 冻结）。配套文件：`docs/operations/SLO.md`。

## 1. 预算定义

- 月度可用性 SLO 99.9% → 每月错误预算 ≈ 43.2 分钟不可用（30 天计）。
- 预算消耗以「外部探针确认的不可用分钟数」计量；单一内部组件报警但未造成用户侧失败的，不扣预算但计入事件复盘。
- 解读任务收敛（p95 ≤ 5 分钟）不按分钟扣可用性预算；以「超出终态时限的任务占比」另设预算：每月 ≤ 5%。

## 2. 预算消耗档位与动作

| 档 | 条件 | 动作 |
|---|---|---|
| 绿 | 月消耗 < 50% | 正常发布与灰度 |
| 黄 | 月消耗 50–100%，或单次事件消耗 > 25% | 冻结非修复类发布；值班人 24h 内出事件报告 |
| 红 | 月消耗 > 100% | 停止放量与新功能发布；只允许可靠性修复；恢复到黄档后解除 |

## 3. Burn rate 告警（Task 8 落地真实路由）

| 告警 | 条件 | 路由 |
|---|---|---|
| 快速燃烧 | 1 小时窗口燃烧率 > 14.4×（2 天内烧完月预算） | 电话/短信 + IM，5 分钟内送达 |
| 慢速燃烧 | 6 小时窗口燃烧率 > 6×（5 天内烧完） | IM + 邮件，30 分钟内确认 |

阈值计算基准：99.9% SLO、30 天预算 43.2 分钟；fast-burn 14.4×、slow-burn 6× 为 Google SRE 多窗口告警的常用起点，首次演练后按实测噪声调整并记录在此文件。

## 4. 与其他告警的关系

业务告警（`runtime_unknown`、`delayed`、Guard rejection、model cost、支付回调失败、队列年龄、备份失败）独立于可用性预算路由到值班；其中任何一类持续 30 分钟未确认即升级为可用性事件计时。
